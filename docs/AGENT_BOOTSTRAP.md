# Optional full project orientation

Use this sequence when the user requests a full orientation or invokes `/initialize`. It is not required at the start of every conversation. Regardless of provider, use `AGENTS.md` for the normal collaboration and approval boundaries.
1. Read `README.md` and `AGENTS.md`.
2. Read `docs/VISION.md`, `docs/ARCHITECTURE.md`, `docs/ROADMAP.md`, and `docs/ASSET_POLICY.md`.
3. Read `docs/OPEN_QUESTIONS.md` and `docs/DECISIONS.md`; check current files, git status, recent commits, and issues if available.
4. Identify what is established versus still a proposal, and note relevant open questions and prior decisions.
5. Return: **Current state**, **non-negotiable invariants**, **open decisions**, **proposed next small task**, **verification plan**.
6. Treat orientation as read-only; wait for an approved implementation phase before modifying the repository.

For authorized implementation, use a focused branch/PR when practical, include tests or validation evidence, and avoid unrelated changes. Update question and decision records within the authorized scope as described in `AGENTS.md`.
